DYTRANOB DOCUMENTATION / ARCHITECTURE

架构

DyTranOb 将原生会话与外部接入分离。HTTP、WebSocket、WebUI、SDK 与 MCP 最终进入同一个 Runtime.execute，避免各入口各自维护业务行为。

text
抖音 IM / Mock
      │ NativeAdapter：字符串 ID、原生事件与操作
      ▼
Runtime：账号选择 → ID 映射 → OneBot 事件 / 动作
      │                      │
      │ RuntimeStore         └─ 动作调度 → NativeAdapter
      ▼
HTTP / WS / SSE / webhook / 反向 WS
      │
      ├─ 浅色 WebUI
      ├─ Node.js SDK
      └─ MCP stdio 服务

事件流与动作流

适配器发布 NativeEvent。每个账号使用独立的 Promise 队列处理原生事件，保留该账号内的处理顺序；运行时将用户、群与消息字符串 ID 映射为数字，生成 OneBot 事件，并写入本地缓存后向接入层发布。

动作请求包含 action、params，以及可选 account_id / self_id。调度器选定账号、反查数字 ID、解析消息段，再调用原生适配器。响应统一为 status、retcode、data 与可选 echo。请求和事件里的 account_id 是本项目扩展字段。

单账号时省略账号选择器即可；多账号的账号相关动作必须指定 account_id 或 self_id。同时填写两个选择器时，二者必须指向同一个账号。get_status 无选择器时返回全局状态。

ID 与存储模型

抖音 ID 可能超过 JavaScript 安全整数范围，因此原生 ID 始终保持字符串。禁止对原生 ID 使用 Number()、parseInt() 或浮点 JSON 字段。

映射键是 [account_id, kind, native_id]，其中 kind 为 user、group 或 message。运行时为其分配 1 到 2147483647 的递增整数别名。相同原生 ID 在不同账号或不同类型中拥有独立映射；反查错误类型、未知 ID 或跨账号 ID 会失败。

映射与最近 5000 条消息保存到 dataDir/onebot-store.json。新增映射先写临时文件再重命名，成功后才对外返回别名。保留相同 account_id 与数据目录可在重启后继续使用原有别名。更换数据目录或删除映射后，旧别名不可继续使用。该文件包含消息正文，备份时按会话敏感数据处理。

数据目录使用 runtime.lock 防止两个进程同时写入。发现旧锁时会检查进程是否仍然存在；不要让多个实例共用数据目录。

ConnectionManager 由 CLI 启动，复用相同的 Runtime，为每个网络连接管理独立的传输生命周期；新增连接不会创建额外的抖音会话。连接列表与递增修订号原子保存到 dataDir/connections.json。变更按顺序执行，持久化或监听失败时不接受新设置；WebUI 的配置状态以服务端返回为准。

控制台端口提供管理 API、WebUI 与文档；连接级别的 HTTP / WS 监听只提供对应 OneBot 入口与最小存活检查，不开放管理 API。WebUI 在 Token 验证成功后才初始化账号、动作、事件与连接视图；每次访问数据接口仍独立校验 Bearer 凭据。

缓存与投递保证

  • get_msg 读取本地最近 5000 条消息，不查询完整云端历史。
  • HTTP 最近事件保留本次运行的最近 200 条；WebUI 只在标签页内保留最近 300 条。
  • 同一账号的原生消息 ID 用于有限去重。去重集合有界，重启后重新建立。
  • WS、SSE 与 webhook 提供在线事件分发，不提供持久化消费位点、完整补发或恰好一次保证。业务消费者应按账号与 message_id 自行去重。
  • 原生撤回和引用所需的会话路由仅在当前进程中保留；重启后的旧消息即使仍能 get_msg，也不保证可撤回或引用。

设计边界

OneBot 是互操作接口，并不使抖音具备 QQ 的全部功能。不存在的原生能力必须返回明确错误，不能用本地假成功替代。Mock 模式用于开发协议行为，不作为原生能力的证据。真实账号依赖上游 SDK、平台状态、权限与验证流程。

DYTRANOB DOCUMENTATION / CONFIGURATION

配置与运行

环境与启动

要求 Node.js 22.5 或更高版本。原生 SDK 使用 Node.js 内置 SQLite，旧版本 Node.js 无法满足运行要求。建议使用受支持的近期 Node.js 版本。

Windows 双击根目录 launcher.bat，程序会一直在 CMD 前台运行。服务就绪后显示 WebUI 地址、当前生效的 Token、HTTP / WebSocket 地址与账号状态；手动打开地址并输入 Token。退出时按 Ctrl+C，启动失败时窗口会保留错误信息。

sh
npm install
npm run dev -- --mock

离线演示会选择 demo 账号并使用当前工作目录下的 data/demo，不访问抖音账号。WebUI 地址默认是 http://127.0.0.1:5088。打开后先显示独立的 Token 登录页；验证成功后才显示控制台、账号与网络配置。登录失败时停留在登录页并显示原因。

sh
npm run dev -- --config dytranob.config.json
npm run build
npm start -- --config dytranob.config.json

未指定 --config 时，CLI 自动寻找当前目录的 dytranob.config.json，否则使用默认配置。--mock 会覆盖账号与数据目录设置。可用 --host、--port 覆盖监听地址。--help 显示完整选项。

WebUI 网络连接

登录工作空间后打开「连接配置」，按连接类型筛选，点击「新增连接」设置名称、地址、令牌与启用状态。卡片可编辑、启用 / 停用或删除。保存会调用运行时接口并写入本地文件，刷新页面或重启后仍保留。

类型type工作方式
HTTP 服务端http新建独立 HTTP 监听端口，接收 OneBot 动作
WebSocket 服务端ws新建独立 WS 监听端口，提供动作与事件
HTTP 上报http_post将事件 POST 到 url，不创建监听端口
反向 WebSocketws_reverse主动连接 url，双向交换动作与事件并自动重连

连接的公共字段为 id、name、type、enabled、token 和 heartbeatInterval。创建时省略 id 会自动生成；名称为 1–80 字符；enabled 默认为 true。心跳间隔默认 15000 毫秒，连接级别支持 0 关闭心跳，最大 3600000 毫秒。

服务端连接额外使用 host、port、allowRemote，默认是 127.0.0.1:3001 与 false。端口 0 请求自动分配，卡片与 API 的 actualPort 显示实际端口；多个连接应使用不同监听端口。非本机监听必须显式开启 allowRemote 且有有效令牌。出站连接必须填写对应 HTTP(S) 或 WS(S) 的 url；令牌放在独立字段，不放在 URL 中。

每个连接使用独立 OneBot Token；创建时留空表示不鉴权，不继承 WebUI Token，也不继承 server.onebotToken。Token 使用不含空格的可见 ASCII 字符，最多 4096 个字符。编辑时不填写新 Token 会保留原设置，明确提交 token: "" 则关闭该连接的鉴权。管理接口不返回令牌明文，tokenConfigured 仅表示是否设置了自定义 Token；未配置连接 Token 时为 false。目标 URL 不接受 #fragment、内嵌用户名密码或凭据查询参数。

控制台 server.port 默认仍为 5088；WebUI、SDK、MCP 的 /api/*（包括 /api/action 调试）和 SSE 使用 WebUI Token。标准 OneBot 动作 /action、/<action>、POST / 以及 /ws 使用独立的 server.onebotToken。新增连接的端口只开放所选传输及 /health，不提供 WebUI、连接管理或账号登录管理接口。

连接保存于 dataDir/connections.json，包含 revision 与连接列表。文件存在时优先读取该文件；配置中的 connections 和旧版 URL 数组只用于首次初始化。后续通过 WebUI 或 API 修改，不要在进程运行时手工编辑文件。无效文件会报告错误，不会静默覆盖。该文件可能含独立连接令牌，需与会话数据一起保管。

连接变更会校验并尝试启动新设置；端口冲突或保存失败时返回错误并保留 / 恢复原设置。修改同一监听端口的 Token 等参数会短暂重启该连接，已有客户端需要重连；仅修改名称不重启传输。程序启动时个别连接无法监听会标记为错误，可在控制台修正。

升级提示：旧连接中省略或留空的 token 现在表示不鉴权；若对端之前配置了 WebUI Token，请改为在两端填写相同的独立连接 Token。非本机监听仍需显式开启 allowRemote 并配置连接 Token。

令牌优先级

DYTRANOB_TOKEN 环境变量优先于 --token，后者优先于配置文件。最终仍为空时，CLI 读取 dataDir/webui.json 的 token；文件尚不存在才生成一次并保存。重启、重建与重新打开 launcher 均复用该值。文件损坏时会报错，不会偷偷生成新值。可以在 dytranob.config.json 的 server.token 中固定指定自己的令牌。显式配置覆盖不会改写保存的自动令牌；移除覆盖后恢复使用原保存值。演示模式与正式模式各用自己的数据目录。

PowerShell：

powershell
$env:DYTRANOB_TOKEN = 'your-long-random-token'
npm run dev -- --mock

POSIX shell：

sh
export DYTRANOB_TOKEN='your-long-random-token'
npm run dev -- --mock

令牌不要放在仓库或 URL 中。WebUI 默认只在内存保存；用户勾选后仅在该标签页 sessionStorage 中保存。

原生账号登录

  1. 配置 type: "douyin" 并启动。
  2. 打开 WebUI，在登录页填写 CMD 启动日志中的 Token，验证后进入控制台。
  3. 在账号会话中点击「扫码登录」，使用抖音 App 扫码并确认。
  4. 如需平台验证，点击 WebUI 中的本机验证链接并手动完成；运行时不自动绕过平台验证。
  5. 等待账号显示在线，再查询好友或发送消息。

启动时会尝试恢复已有会话。二维码状态和验证信息仅通过认证后的登录接口提供。二维码过期或登录失败后，可再次启动扫码流程；若上游 SDK 流程尚未退出，可重启运行时后重试。

原生会话数据保存于 dataDir/accounts/<account_id>。不要重命名已使用的账号 ID 后继续复用旧 OneBot 别名。首次真实登录及平台验证需要网络；真实账号端到端行为尚未在本项目中验证。

多账号

json
{
  "accounts": [
    { "id": "work", "type": "douyin" },
    { "id": "personal", "type": "douyin" }

}

每个账号使用独立原生会话目录。账号相关动作需指定 account_id 或已映射的 self_id，事件携带 account_id 与 self_id。扩展动作 dy_list_accounts 可查询当前账号。只有一个账号在线时，未指定账号的动作默认路由到该在线账号。

AstrBot 媒体地址

可选 server.mediaPublicUrl 设置 AstrBot 能访问的运行时基础 URL，默认使用主监听端口的本机地址。AstrBot 在 Docker 或远程主机时通常需要设置。媒体缓存默认 1 小时、128 MiB，不持久化；完整配置、重启后的图片测试和网页会话参数见 抖音扩展与媒体接入。

DYTRANOB DOCUMENTATION / API

动作与事件

DyTranOb 实现 OneBot v11 的实用子集，并提供 dy_* 扩展。运行中可通过 GET /api/actions 获取当前的 45 个动作及参数 JSON Schema。目录包含协议入口，不代表每个原生账号均有权限执行。

机器人接入的完整参数与返回说明见 AstrBot 接口手册。静态机器可读 Schema 位于 /docs/actions.json；作品详情和字幕分别使用 dy_get_video_detail、dy_get_video_subtitles。

请求与响应

json
{
  "action": "send_private_msg",
  "account_id": "main",
  "params": {
    "user_id": 2,
    "message": [{ "type": "text", "data": { "text": "你好" } }]
  },
  "echo": "request-1"
}

示例中的 user_id: 2 是示意值，请使用好友列表或 dy_resolve_id 返回的实际别名。请求里的数字 ID 均是当前运行时映射后的 OneBot ID。

json
{
  "status": "ok",
  "retcode": 0,
  "data": { "message_id": 4 },
  "echo": "request-1"
}

失败响应的 status 为 failed，data 为 null，并提供 message / wording。HTTP 200 仍可能包含动作失败，调用端必须检查 status 与 retcode。echo 原样返回。多账号需使用 account_id 或 self_id 选择账号，详见架构文档。

参数与 ID

完整 JSON Schema 由 GET /api/actions 提供，WebUI 的动作调试同步展示。新增动作严格校验参数；不接受未知字段。

原生 native_user_id、conversation_short_id、item_id、aweme_id 和游标都用字符串，避免 64 位 ID 精度丢失。sec_user_id 是用户主页的加密 ID，不等同于数字 UID。原生扩展返回的数据保留平台字段；不要把原生字符串 ID 直接传给要求 OneBot 整数的旧动作。

四个会话发送动作（文本、图片、动态表情、作品卡片）必须选择一种目标：

json
{ "native_user_id": "1234567890123456789" }
json
{
  "conversation_id": "0:1:1234567890123456789:987654321098765432",
  "conversation_short_id": "7123456789012345678",
  "is_group": false
}

前者会创建私信会话；后者可直接使用已知会话，群聊设置 is_group: true。不要同时填写两种目标。发送成功返回本地 message_id、原生 native_message_id 及会话 ID，并产生 message_sent 事件，可使用 delete_msg 在本次运行期间尝试撤回。

dy_send_image 只能填写 image_base64 或 image 之一。Base64 支持纯内容或 base64:// 前缀，解码后最大 16 MiB。普通 OneBot image 消息段也支持 file: "base64://..."，建议用消息段数组；CQ 字符串仍有 100000 字符上限。HTTP / WS 总请求上限为 24 MiB，图文混合与多图会拆成多条原生消息，仍不接受服务端文件路径。

作品与评论的 count 范围 1–100，默认 20；作品 max_cursor、评论 cursor 初始为 "0"。聚合响应含 complete：平台无更多数据或数量已满足时为 true；达到分页上限、游标不推进时可能为 false。不能把 complete:false 当作已抓取全部作品。

陌生人接口 count 限制每次返回的会话数，指定 conversation_short_id 时限制消息数。首次 cursor: "0"，以后将返回的 next_cursor 原样传回；它可能包含冒号表示平台批次中的位置。停止条件是 has_more: false。列表在两次请求间可能变化，业务端可按会话或消息 ID 去重。

AstrBot 图片与表情

smart_imagechat_hub 插件发送图片

该插件使用 Image.fromFileSystem 构造图片，本机 AstrBot 的 aiocqhttp 适配器会读取图片并转换为 OneBot image.data.file = "base64://..."。开启自定义回复或追加表情时，可能把文字与图片放在同一条消息链中。DyTranOb 已支持这类消息链，无需更改插件或开放服务端文件读取。

send_private_msg / send_group_msg / send_msg 遇到图文或多图时，按原顺序拆成连续文本与单张图片，最多 20 条。发送前校验所有分段；同一会话的这些标准发送动作依次执行，避免两条回复的分段交错。图片带引用且前面没有文字时，先发送引用原消息的 [图片] 文本，再发图片。

成功的 message_id 对应最后一条真实消息；拆分时额外返回 message_ids，包含全部真实消息 ID。每条都会产生 message_sent 事件，可分别查询与撤回。若平台在中途拒绝，返回失败，message / wording 的 message_ids=... 列出已发出的部分；剩余分段停止，不会自动重发整条消息链。整条重试可能重复已发送的文字或图片。

接收图片的解密与缓存

普通私信图片可能是 AES-256-GCM 容器，不能直接交给 AstrBot 图片下载器。现在接收链路会尝试原图与缩略图地址，使用消息里的 skey 解密并验证 PNG / JPEG / GIF / WebP 文件头，再生成标准 OneBot image 段。表情优先取 URL 列表，避开 SDK 1.1.0 把不透明 uri 当成网址的问题；GIF 字节不转码。

图片放在进程内缓存中，默认总上限 128 MiB、单张 16 MiB、有效期 1 小时；达到容量上限时按先后顺序淘汰。地址形如 http://127.0.0.1:5088/media/<随机标识>.png。持有地址即可读取该张图片，不需要也不包含 WebUI Token。接口只读取缓存，不接受任意 URL 下载或文件路径。重启、过期、淘汰后返回 404；历史事件仍可存在，但旧图片链接不保证可用。

如果 AstrBot 在 Docker、另一台电脑或远程服务器上，请在主配置中增加 AstrBot 能访问的地址：

json
{
  "server": {
    "host": "0.0.0.0",
    "port": 5088,
    "allowRemote": true,
    "token": "你的固定WebUI令牌",
    "onebotToken": "你的OneBot令牌",
    "mediaPublicUrl": "http://192.168.1.100:5088"
  }
}

将 IP 替换为运行 DyTranOb 的电脑地址，并配置网络可达性。使用反向代理时也可以设置 HTTPS 基础地址。mediaPublicUrl 仅影响事件里的图片地址，不会自动开端口或改防火墙。

重启运行时后重新发送一张图片或表情测试。旧缓存事件没有保存解密密钥，不会自动补修历史链接。下载或解密失败时上报明确的文字占位并记录消息 ID，避免向 AstrBot 发送无法解码的加密内容。HEIC、缺少资源 / 密钥、过期 CDN 地址仍可能失败；图片下载最多尝试 4 个地址，每次最多 15 秒，消息按账号排队，最多积压 128 条。

网页接口的登录态

默认复用当前账号的 douyin-im 登录会话、设备参数和可用的 ticket guard 绑定。网页接口会生成 a_bogus，图文上传采用 ImageX V4 签名；仅访问固定平台端点。返回校验失败、缺少 comment.cid 或上传未确认时，都不会返回伪造成功。

如果同一个账号的网页接口要求单独的浏览器参数，可在 dataDir/accounts/<账号ID>/web-session.json 手动补充以下可选字段。文件每次执行扩展动作时读取，不需要重启：

json
{
  "cookies": "同一账号的有效网页 Cookie",
  "userAgent": "获取这些 Cookie 时的浏览器 User-Agent",
  "msToken": "同一网页会话的 msToken",
  "webId": "网页数字 webid",
  "uifid": "网页 uifid",
  "fp": "网页 verifyFp",
  "sessionTrait": "网页 x-tt-session-dtrait"
}

此文件不是 WebUI Token 配置，也不会修改主 IM 登录。字段可以省略；不要把示例占位内容当作真实凭据。文件不经 WebUI/API 返回，必须保护其中凭据。补充 Cookie 不保证通过平台验证：会话、签名绑定、网络环境和账号权限可能需要同时匹配。无需将凭据发给开发者，诊断时只提供动作名、返回码和已脱敏日志。

也支持使用浏览器中的原始名称 UIFID、ttwid、s_v_web_id。UIFID 等价于 uifid，s_v_web_id 等价于 fp；同一项同时写两种名称时值必须相同。单独填写的值会覆盖 Cookie 中的旧值：UIFID 同时用于 Cookie、请求头和 query，s_v_web_id 同时用于 Cookie 与 fp/verifyFp，ttwid 放入 Cookie。不要把 ttwid 填成数字 webId。

推荐在本地登录抖音网页，按 F12 打开开发者工具，在 Network 中刷新并查找 aweme/detail 请求；将同一次请求的 Cookie 和 User-Agent 填入文件。Application → Cookies → 抖音域名也可查看 UIFID、ttwid、s_v_web_id；若看不到对应 Cookie，可检查该成功请求的 uifid 请求头和 fp/verifyFp 参数，不能随机编造。完整网页 Cookie 会替换网页请求原来使用的 IM Cookie，避免混合不同会话。

3. 通用请求与响应

json
{
  "action": "dy_get_video_subtitles",
  "account_id": "001",
  "params": { "aweme_id": "7123456789012345678" },
  "echo": "subtitles-1"
}

HTTP：将上述 JSON POST 到 /action。WS：直接发送上述 JSON 帧，用 echo 匹配返回帧，同时处理异步事件。不要按返回顺序匹配请求。

json
{
  "status": "ok",
  "retcode": 0,
  "data": { "available": false, "reason": "no_subtitle_metadata", "text": "", "cues": [] },
  "echo": "subtitles-1"
}

这个响应仅展示主要字段。HTTP 200 不等于动作成功：原始 HTTP/WS 客户端必须同时检查 status == "ok" 和 retcode == 0。失败响应为 status: "failed"、非零 retcode、data: null，并提供 message / wording。aiocqhttp 的 call_action 和 DyTranOb SDK 已解包成功的 data，失败时抛出异常；不要再对返回值取一次 data。

ID 规则：OneBot 的 user_id、group_id、message_id 使用本地稳定整数别名；抖音的 aweme_id、item_id、native_user_id、conversation_short_id 都必须使用十进制字符串。不要把 19 位作品 ID 转成 JavaScript Number；不要把消息 ID 当成作品 ID。sec_user_id 是主页的加密用户标识，也不等于数字 UID。

4. 从视频分享卡片读取字幕

  1. 接收 post_type: "message" 的分享事件，读取 dy.work.item_id。避免处理自己的 message_sent 造成循环。
  2. 若 AstrBot 适配器未保留 dy 字段，用当前消息的 OneBot message_id 调用 get_msg，读取 data.dy.work。本地最多缓存最近 5000 条消息，重启仍可保留已缓存的内容。
  3. 调用 dy_get_video_subtitles，传入 aweme_id: work.item_id；有 work.conversation_short_id 时一并传入，优先使用原生私信详情接口。
  4. 只有 available: true 才把 text 当作字幕；时间轴在 cues 中，单位为秒。
  5. available: false 时查看 reason 和 warnings，说明当前没有取得字幕数据，不要用标题、作品描述、评论或视频画面文字假装字幕。

参数类型必填说明

返回 data：

  • aweme_detail：平台原始作品对象，包含可能存在的 desc、author、statistics、video、images 等字段，不承诺所有作品都有相同字段。访问字幕原始信息用 aweme_detail.video.cla_info。

warnings 可能包含 WEB_DETAIL_UIFID_REQUIRED、WEB_DETAIL_UNAVAILABLE、IM_DETAIL_UNAVAILABLE、MOBILE_DETAIL_UNAVAILABLE。WEB_DETAIL_UIFID_REQUIRED 表示网页端要求的 UIFID 缺失。私信已登录与完整网页登录态是两个条件；现有 web-session.json 配置方法见 扩展文档。同一浏览器的 Cookie、UA、UIFID、fp 需要匹配，不要随机填值。

机器人不需要持有这些凭据。由用户在 DyTranOb 本机的 data/accounts/<账号ID>/web-session.json 填写同一次浏览器会话的完整 cookies 和 userAgent，或补充原始字段 UIFID、ttwid、s_v_web_id（旧名 uifid/fp 仍兼容）。DyTranOb 会将这些值用于网页请求；机器人继续仅传 aweme_id 和可选 conversation_short_id。字段名是 cla_info，不是 cal_info。补齐浏览器标识后仍可能要求有效的网页签名，不能承诺补三个值就一定取得字幕。

每个字幕文件上限 2 MiB，最多 20000 个 cue、500000 字符文本；超限明确失败，不静默返回残缺文本。字幕下载总预算 30 秒，校验每次重定向的官方 CDN 域名，不携带账号 Cookie。字幕地址可能过期，应存储成功返回的文本，不把签名 URL 当永久地址。建议外部调用超时设为 130–180 秒；SDK 的详情/字幕默认超时分别为 90/125 秒。

本功能获取平台已有字幕，不执行 OCR 或语音转写。画面上压制的字幕、音乐歌词、视频描述不等于可下载字幕轨道；若平台不提供，需由 AstrBot 另行配置视频理解或语音识别工具，不能由此接口凭空生成。

5. AstrBot Python 调用示例

以下函数供已有 AstrBot 插件/工具调用，不会自动注册成大模型工具。适用 AstrBot 的 aiocqhttp / OneBot v11 事件；反向 WS 已绑定对应账号。

python
import asyncio
from astrbot.core.platform.sources.aiocqhttp.aiocqhttp_message_event import AiocqhttpMessageEvent

async def read_shared_subtitles(event: AiocqhttpMessageEvent) -> dict:
    # call_action 返回解包后的 data，失败时抛出异常。
    cached = await event.bot.call_action(
        "get_msg", message_id=int(event.message_obj.message_id)
    )
    work = (cached.get("dy") or {}).get("work") or {}
    aweme_id = work.get("item_id")
    if not isinstance(aweme_id, str) or not aweme_id.isdecimal():
        return {"available": False, "reason": "message_has_no_work_id"}
    params = {"aweme_id": aweme_id}
    if work.get("conversation_short_id"):
        params["conversation_short_id"] = work["conversation_short_id"]
    result = await asyncio.wait_for(
        event.bot.call_action("dy_get_video_subtitles", **params), timeout=150
    )
    return result  # 给模型 text/cues/available/reason/warnings，按状态决定回答。

若已有作品 ID，可直接调用 await event.bot.call_action("dy_get_video_subtitles", aweme_id="7123456789012345678")。查询错误应交给调用工具的异常处理返回，不要写成空字符串并当作成功。AstrBot 自身的 OneBot API 超时也应大于查询预算；只增加 asyncio.wait_for 不会延长内部更短的超时。

分页 count/page_size 范围 1–100，默认 20。作品/评论游标为字符串；陌生人 next_cursor 可能含冒号，必须原样回传。has_more=false 时停止；complete=false 时不能声称已经获取全部。结果可按原生 ID 去重，不要无限重试重复游标。

发送 message 推荐使用 OneBot 数组，例如 [{"type":"text","data":{"text":"你好"}}]。图片使用 {"type":"image","data":{"file":"base64://图片内容"}} 或可访问的 HTTPS 地址；最大 16 MiB。AstrBot 本地文件应由客户端读成 Base64，不能把 Windows 路径交给 DyTranOb 服务读取。图文和多图会按顺序拆为最多 20 条原生消息；返回 message_id 是最后一条，message_ids 包含所有已成功发送的 ID。部分失败会在 message 中列出已发送 ID，不能重试整条消息以免重复。

原生文本参数通常为 1–10000 字符。原生视频文件、语音、QQ 专属功能和插件系统不在当前实现范围。reply 引用需要当前运行已观察到的消息路由；图片带引用可能先发送引用占位文字再发送图片。

传输、SDK 与 MCP

HTTP

默认控制台端口的 /api/* 与 SSE 使用 WebUI Token；标准 OneBot HTTP 动作 /action、/<action>、POST / 和 WS 使用 server.onebotToken，留空时不鉴权。连接管理创建的独立端口与出站连接仅使用各自的 token，留空不鉴权。设置 Token 后使用 Authorization: Bearer <token>。WebUI 静态资源、公开开发文档与最小 /health 检查不需要凭据。优先使用请求头，避免令牌进入浏览器历史或代理日志。

sh
curl http://127.0.0.1:5088/api/action \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"get_status","params":{},"echo":"example"}'
入口说明
POST /api/auth验证 Bearer Token；成功时 data: {authenticated:true}，失败为 HTTP 401
POST /api/actionWebUI / SDK / MCP 管理动作调试；默认端口使用 WebUI Token
POST /action 或 POST /OneBot 标准动作对象 {action, params, account_id?, self_id?, echo?}；默认端口使用 server.onebotToken
GET /<action> 或 POST /<action>OneBot 简写调用；参数平铺，账号选择器与 echo 保留
GET /api/statusdata: {accounts,version,uptime}；uptime 为秒
GET /api/actionsdata: [{action,description,params}]，params 为 JSON Schema
GET /api/events?limit=100本次运行最近事件，较早到较晚排列；最多实际保留 200 条
POST /api/accounts/:id/login/qr启动或继续账号原生二维码登录
GET /api/accounts/:id/login登录状态、二维码与待验证信息
GET /eventstext/event-stream 的实时事件流
GET /health仅检查 HTTP 服务存活，不代表账号在线

/api/* 查询与登录接口均返回 {status,retcode,data} 包装，不能直接把 HTTP JSON 当成 data 使用。HTTP 请求体与 WS 消息最大为 24 MiB（支持 Base64 图片）。

登录状态的 data 包含 state、online，以及可选 account、qrcodeBase64、qrcodeUrl、expireTime、qrStatus、error、verification。verification.url 是需要手动打开的本机验证页面，按敏感数据处理。

连接管理 API

以下接口位于控制台端口，均要求控制台 Bearer Token，响应使用相同的 {status,retcode,data} 包装。新增的传输端口不开放管理接口。

入口成功响应
GET /api/connectionsHTTP 200；data: {revision,connections}
POST /api/connectionsHTTP 201；data 为创建后的连接视图
PUT /api/connections/:idHTTP 200；部分更新，data 为更新后的连接视图
DELETE /api/connections/:idHTTP 200；data: null，关闭连接并删除持久化配置

创建请求示例：

json
{
  "name": "本地机器人",
  "type": "ws",
  "enabled": true,
  "host": "127.0.0.1",
  "port": 3001,
  "heartbeatInterval": 15000
}

type 支持 http、ws、http_post、ws_reverse；出站类型使用 url。可选 token 配置连接专用凭据；编辑省略该字段时保留，空字符串则关闭连接鉴权；创建时省略也不鉴权，不继承 WebUI Token。返回的视图不含 token，包含 tokenConfigured、status，以及适用时的 actualPort 和 error。状态为 running、stopped、connecting、connected 或 error；HTTP 上报的 running 表示上报通道已启用，不保证目标服务可达。

保存会立即应用并写入 dataDir/connections.json。校验失败返回 1400，未知 ID 返回 1404，重复 ID、端口占用或无法启动连接返回 1409；持久化失败返回 1500，变更不作为成功接受。完整字段、默认值与首次配置迁移规则见 配置与运行。

正向 WebSocket

通用入口：ws://127.0.0.1:5088/ws，发送标准动作 JSON，接收带 echo 的响应与实时事件。纯动作入口为 /ws/api，纯事件入口为 /ws/event；兼容别名为 /api、/event 与通用 /。

通过连接管理创建的 ws 服务端使用自己的监听端口，提供同样的 WS 路径。http 服务端只接收动作，支持 POST /action、POST /api/action、POST / 与 GET /<action> / POST /<action>，不提供 WS、SSE 或管理接口。

ts
import WebSocket from 'ws';

const ws = new WebSocket('ws://127.0.0.1:5088/ws', {
  headers: { Authorization: `Bearer ${process.env.DYTRANOB_ONEBOT_TOKEN}` },
});
ws.on('open', () => ws.send(JSON.stringify({
  action: 'get_status', params: {}, echo: 'ws-1',
})));
ws.on('message', data => console.log(JSON.parse(data.toString())));

以 post_type 区分事件，以 echo 关联动作。事件入口拒绝动作请求，纯动作入口不推送事件。SDK 可以处理连接重建与请求关联。

浏览器原生 WebSocket 不能自定义请求头。服务端兼容 access_token 查询参数，但 WebUI 采用带 Bearer 的 fetch SSE，以免把令牌写入 URL。自行构建浏览器客户端时也建议使用该方式。

SSE

GET /events 返回 data: <OneBot JSON>。客户端使用带认证请求头的 fetch，并按 SSE 帧分隔读取。WebUI 实现位于 webui/ui.js，包含断线重连。SSE 无持久化 cursor，重连可能存在间隙；GET /api/events 只补充有界最近事件。

反向 WebSocket 与 webhook

ws_reverse 连接的目标由运行时主动建立通用 WS 连接。握手含 X-Client-Role: Universal、X-Self-ID、User-Agent，仅在该连接设置了 Token 时发送 Bearer 头；留空时不携带 Authorization，不发送 WebUI Token。每个已登录账号各建立一条连接，X-Self-ID 为该账号的 OneBot self_id；账号登录完成前不会连接（不会以 X-Self-ID: 0 握手），新增或移除账号时自动建立或关闭对应连接。每条连接只推送所属账号的事件，未指定 account_id/self_id 的动作默认由该账号执行。失败后采用有上限的退避重连；接收端用标准动作对象回调运行时。旧配置 reverseWsUrls 首次启动时迁移为此类连接。

http_post 连接向目标发送 OneBot 事件的 HTTP POST。使用有效令牌时，X-Signature 为 sha1= 加上使用该连接令牌对原始请求体计算的 HMAC-SHA1 十六进制值。接收端验证签名时必须使用原始字节，不要重新序列化 JSON。旧配置 webhookUrls 首次启动时迁移为此类连接。

每个 webhook 目标使用独立有界队列；积压超过 256 条会丢弃新事件，单次请求超时 10 秒，失败不保证重试。当前版本不提供持久化可靠投递。

当前版本不解析 webhook 响应体，不支持 OneBot webhook 快速操作。接收事件后如需回复或审批，请通过认证后的 HTTP 或 WS 动作入口调用。接收端应返回成功 HTTP 状态，并自行处理持久化与幂等。

AstrBot 对接

AstrBot 的 OneBot v11 适配器接收反向 WebSocket。先在 AstrBot 创建 OneBot v11 机器人并启动监听，再在本 WebUI「连接配置」新增「反向 WebSocket」，URL 填写 AstrBot 提供的完整地址（包含其路径）。两端在同一台机器时可用 ws://127.0.0.1:6199/ws，端口和路径以你的 AstrBot 配置为准；容器部署填写运行时能访问的宿主机地址。

  • AstrBot 的 ws_reverse_token 为空：本连接 Token 也留空。
  • AstrBot 设置了 ws_reverse_token：本连接填写完全相同的固定 Token。
  • WebUI 登录 Token 只用于管理，不填写到 AstrBot，除非你主动为连接选用了相同字符串。

连接成功后，AstrBot 使用同一条 WS 发送 { "action": "get_friend_list", "params": {}, "echo": "request-1" }，并按 echo 接收动作结果；不需要访问 /api/actions 或登录 WebUI。45 个动作入口共用同一分发器；原生 SDK 未支持的能力仍返回不支持错误，详见动作文档。

实现参考：AstrBot OneBot v11 适配器、SnowLuma OneBot 鉴权。

Node.js SDK

SDK 的管理方法及默认 call() 使用 /api/* 和 WebUI Token。若给默认 WS 单独设置了 server.onebotToken，请使用第二个 SDK 实例（token 为该 OneBot Token）调用 connect() / callWs()；连接到独立 HTTP 端口时 call() 使用该连接 Token，管理查询不开放。程序化 startServer() 的 onebotToken 省略时保留旧的单 Token 模式；CLI 始终显式传入独立配置。

SDK 是 Node.js 客户端，使用 EventEmitter 和 ws，不直接作为浏览器脚本加载。

ts
import { DyTranObClient, ActionError } from 'dytranob/sdk';

const client = new DyTranObClient({
  baseUrl: 'http://127.0.0.1:5088',
  token: process.env.DYTRANOB_TOKEN,
  timeout: 15000,
  reconnect: true,
});

try {
  const status = await client.status();
  console.log(status.accounts);
  const friends = await client.call<Array<{user_id:number;nickname:string}>>(
    'get_friend_list', {}, { account_id: 'main' },
  );
  console.log(friends);
} catch (error) {
  if (error instanceof ActionError) console.error(error.retcode);
  else throw error;
}

client.on('event', event => console.log(event));
client.on('transport_error', error => console.error(error.message));
client.on('connected', () => console.log('connected'));
client.on('disconnected', code => console.log('disconnected', code));
await client.connect();
const version = await client.callWs('get_version_info');
console.log(version);
// 在应用退出时调用 client.close()，终止 WS、重连与挂起请求。

client.call、callWs 与辅助方法返回已解包的 data，失败时抛异常。call 使用 HTTP，connect 订阅 WS 事件，callWs 在通用 WS 上调用动作。断线后挂起的 WS 动作会失败，不自动重发，以避免重复发送消息。

辅助方法：status、actions、recentEvents、startQrLogin、loginState、sendPrivateMessage、sendGroupMessage。createClient(options) 等价于构造 DyTranObClient。动作选择器命名为 account_id / self_id。

仓库内先执行 npm run build，再运行 npm exec tsx examples/sdk.ts；发布或本地安装包后可使用 dytranob/sdk 包导入。当前文档不假设该名称已经发布到 npm。

import { Runtime, MockAdapter, startServer } from 'dytranob';

添加适配器

适配器是编译时源码扩展，项目不提供插件加载、插件市场或第三方脚本执行系统。遵循 src/adapters/types.ts 中的 NativeAdapter：

  1. 实现 connect、disconnect、isOnline，保证可清理监听器和原生资源。
  2. 实现用户、好友、群、成员查询；所有平台 ID 保持字符串。
  3. 将原生消息转为 NativeMessage，使用 publish({type:'message',message}) 发布。
  4. 通过 publish 提供连接、请求与通知事件；适配器内不直接生成 OneBot wire 对象。
  5. 实现 sendMessage、撤回、群操作与申请操作。缺失能力抛出 UnsupportedAdapterOperation，不要返回假成功。
  6. 实现 startQrLogin / getLoginState 或适合平台的状态描述。
  7. 在 Runtime 构造参数中注册适配器；若需配置与 CLI 创建，同时扩展配置枚举和构造工厂。

当前 kind 类型限制为 douyin | mock，添加其他平台时需要相应扩大联合类型。DouyinAdapter 的 createClient 依赖注入点用于隔离原生 SDK 生命周期测试，避免测试访问真实账号。

适配器发布诊断应使用 diagnostic；禁止将 Cookie、令牌、QR 内容、平台验证链接和请求头写入诊断。运行时进一步做有限脱敏，不能代替适配器自身约束。

增加动作

动作应在 src/runtime.ts 的目录中定义名称、描述与 JSON Schema，并在调度器实现参数校验与行为。WebUI 会从 /api/actions 动态加载，无需手工添加动作按钮。

当前 Schema 用于发现和编辑提示，运行时仍需明确校验所有新参数；不要依赖前端校验。若动作允许通过 MCP 使用，应同时检查 READ_ACTIONS / WRITE_ACTIONS 白名单、输入 Schema 与工具注解，避免读取通道间接触发平台写操作。

安全与运维

访问与部署

CLI 默认只监听 127.0.0.1:5088，WebUI / 管理 API 和 SSE 始终需要 WebUI Token。未配置时首次生成并保存到 dataDir/webui.json，后续重启复用。标准 OneBot HTTP / WS 使用独立 Token，默认留空不鉴权。/health 与静态 WebUI / 文档公开。/media/<随机标识> 是单张图片的临时凭证地址，持有者可直接读取，不使用管理 Token；详见扩展文档。

WebUI 先显示独立的 Token 登录页，通过服务端认证后才加载工作空间。所有数据请求继续使用请求头 Bearer 认证，包括 SSE；登录页不是数据接口的认证替代。令牌默认只存在标签页内存，勾选保存时使用 sessionStorage，不会写入 URL 或 localStorage。退出登录会清除当前凭据并返回登录页；凭据失效时也返回登录页。

控制台远程监听需要 server.allowRemote: true 与非空 WebUI Token；默认端口的 OneBot 入口如需鉴权须另设 server.onebotToken；建议置于 HTTPS 反向代理后，并限制网络访问。运行时不内置 TLS、用户账号体系、细粒度 RBAC、逐动作权限或审计存储。一个访问令牌能操作所有配置账号。

HTTP / WS 检查存在的 Origin 头，拒绝不匹配的来源；这不是替代令牌或网络隔离的权限系统。服务设置内容类型、防 MIME 嗅探与 CSP，浏览器端不执行事件里的 HTML。

服务端为兼容 OneBot 客户端支持 access_token 查询参数，但建议使用请求头；URL 凭据可能留在客户端、代理或接收端日志。SDK 使用请求头，不跟随 HTTP 重定向。

数据目录

dataDir/accounts 含原生会话；onebot-store.json 含 ID 映射与最近消息正文；connections.json 可能包含独立连接 Token；webui.json 保存自动生成的固定 WebUI Token。它们与二维码、验证链接、环境令牌同属敏感数据，不提交到 Git，不公开打包，不放入网页静态目录。连接管理 API 返回凭据配置状态，不返回 Token 明文。

备份时先停止运行时，同时备份原生会话与映射文件；恢复后保留相同账号 ID。只恢复其中一部分可能使历史别名、会话或引用路由失效。ID 别名是运行时本地数据，不能直接跨独立实例共享。

Unix 文件模式会尽力限制权限；Windows 需通过文件 ACL 控制用户访问。不要依赖跨平台 mode 数值替代 Windows 权限设置。

外部连接与媒体

webhook 会收到消息和事件正文；反向 WS 接收端能调用动作，并可能收到访问令牌。只配置可信服务。当前版本不处理 webhook 返回的快速操作；回复和审批应使用认证动作入口。

WebUI 可即时管理独立 HTTP / WS 监听和出站连接。连接级别的 Token 独立保存；留空表示不鉴权，不会发送控制台 Token；控制台凭据依然具有全部账号和连接管理能力。非本机监听需要显式开启远程绑定并有有效令牌。

图片发送会触发原生 SDK 访问指定 HTTPS URL；不要将不可信用户提供的任意链接直接作为媒体发送地址。应用若向外提供动作代理，应自行增加目标校验、媒体域名白名单、频率限制与业务权限。

MCP 默认只提供平台查询与本地 ID 映射。--allow-write 开放实际发送、撤回、群操作、图片上传与评论发布，使用者需要控制可调用该工具的客户端与模型工作流。MCP 工具注解是能力说明，不是用户权限系统。
